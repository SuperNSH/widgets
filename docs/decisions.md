# Decisions

Each entry says what was chosen and why.

1. **One generic renderer per platform, driven by an IR, instead of native code per widget.** An NSH app is TSX or Rust; asking it to write SwiftUI and RemoteViews for every widget defeats the point. The app writes a tree of primitives (Widget Tree IR v1, [ir.md](ir.md)) and data; `NshWidgets.swift` and `NshWidgets.java` draw any tree. A new widget is new data, not a new native build. The cost is that the IR offers only what every renderer can draw, and platform gaps show up as fallbacks ([capabilities.md](capabilities.md)).

2. **Two TS layers: base and kit.** `base.ts` holds the primitives, the class resolver and theme tokens, with no look of its own, as `nsh/base` is to NSH apps and gpui-base to GPUI Kit. `kit.ts` holds styled components built only from base nodes. The kit can grow and restyle without touching a renderer, and an app that wants its own look skips the kit.

3. **`widgets.json` beside `nsh.json`.** NSH warns about `nsh.json` keys it does not know, so the App Group and the kinds live in their own file. `nsh-widgets build` writes only the keys NSH itself reads (`ios`, `macos`, `android.libraries`) into `nsh.json`.

4. **Android provider slots with the kind as meta-data.** Android names an `AppWidgetProvider` by its class, and a prebuilt library cannot compile a class per app kind. The AAR ships `NshWidgetProvider$Slot1` to `$Slot16`; the app's manifest gives each kind a slot and names the kind in the receiver's `dev.supernsh.widgets.kind` meta-data. Sixteen slots set the limit of 16 kinds; WidgetKit bundles group ten widgets per block, so two blocks cover them.

5. **The app's per-kind AAR is generated by the CLI and merged by NSH.** The crate's AAR holds what every app shares: renderer, layouts, icons, slots and the action receiver. What differs per app (the slot receivers, `appwidget-provider` XML per kind, description strings) goes into `.nsh-widgets/android/nsh-widgets-app.aar`, which `build` lists in `nsh.json` `android.libraries`. NSH merges both manifests when it packages the app.

6. **One writer per file, atomic renames, an action inbox the app drains.** `snapshot.json` is written only by the app. `data.json` is written by the app and by widget buttons, always through a temporary file and a rename, so neither side reads half a file. Presses append to `actions.jsonl`; `take_actions` moves it aside before reading, so each event is returned once and a press during a read starts a new inbox. Widget events carry a UUID so the app can tell them apart. `update_data` merges top-level keys so an app update does not overwrite a key the widget just changed, unless the patch names it.

7. **System font on Android.** RemoteViews cannot set a typeface, and bundled and downloadable fonts both failed in the widget's restricted inflation context. Android widgets use `sans-serif` with the IR's weight. Fonts in `widgets.json` apply to iOS and macOS only.

8. **iOS toggles as checklist rows.** A WidgetKit `Toggle` draws only a tinted pill that hides a tinted label when on, and forcing `.switch` shows the unsupported placeholder. A button with a check circle, run through the same App Intent, reads clearly in both states. Android 12+ gets a real `Switch`.

9. **Build the extension without an Xcode project.** `nsh-widgets build` runs `swiftc -application-extension` with `-Xlinker -e -Xlinker _NSExtensionMain` (without that entry point the extension crashes in Apple's extension bootstrap), then `xcrun appintentsmetadataprocessor` for the App Intents metadata (without it a widget button fails with "There is no metadata"). The renderer and a generated `WidgetBundle` are the only sources. No `.xcodeproj` to generate, check in or keep in sync.

10. **Require NSH main after longbridge/nsh#2879.** Embedding an app extension needs `ios.extensions` and `macos.extensions` in `nsh.json`, merged on 2026-11-23, and Android needs `android.libraries` with AAR manifest merging. The NSH 0.6.0 release has neither, so the library targets NSH main at or after `5aa56b19` until a release ships them.
