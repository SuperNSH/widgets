# AGENTS.md

Hard rules for humans and coding agents in this repo.

- The main branch is `master`.
- Commit small changes with a short conventional message. No attribution lines.
- Comments are 1-2 lines and state a non-obvious constraint.
- Docs read like a competent human wrote them: direct, concrete, no marketing filler.
- Every behaviour change needs a test. A test is seen to fail once before it counts.
- Local simulator and emulator runs are allowed here, because a widget needs a home screen to be seen. Use simulators and AVDs named after this repo (for example `nsh-widgets-iphone`). Never erase, shut down or kill a simulator, emulator or process you did not create.
- Status claims in README and docs need evidence under `docs/evidence/`: a screenshot someone looked at, or a command and its output. A claim with no evidence is marked unverified.
- The renderers stay generic. No widget-specific code in `NshWidgets.swift`, `NshActivities.swift`, the Java renderer or `NshNode.qml`; a widget is data, never a native class. Per-app code (option enums, controls, tile and slot entries) is generated by `nsh-widgets build` from `widgets.json`.
- The kit (`packages/nsh-widgets/src/kit.ts`) compiles only to base nodes. A kit change never needs a renderer change.
- An IR change lands in every renderer together: the TS types (`base.ts`), the check in `src/store.rs`, the Swift renderer, the Java renderer, the KDE QML renderer (`crates/nsh-widgets-cli/plasma/NshNode.qml`), the GNOME Shell renderer (`crates/nsh-widgets-cli/gnome/extension.js`; run `scripts/gnome-probe` on each listed GNOME version, since St changes between them) and the CLI's `render.rs` (preview and show). Update [docs/ir.md](docs/ir.md) and [docs/capabilities.md](docs/capabilities.md) with it.
- Live Activity attributes (`NshActivityAttributes`) exist twice, in `swift/Bridge.swift` and `crates/nsh-widgets-cli/renderer/NshActivities.swift`. ActivityKit pairs them by name and shape: change both together.
- After changing the Java sources, layouts or drawables, rebuild `android/nsh-widgets.aar` with `scripts/build-aar.sh`. The AAR is committed, and CI's `scripts/check-aar.sh` fails when it is stale.

## Checks

- `cargo fmt --all -- --check`
- `cargo clippy --all-targets -- -D warnings`
- `cargo test --workspace`
- in `packages/nsh-widgets`: `nsh check`, `nsh test`
- in `examples/gallery`: `nsh check` (NSH main or nightly)
- for a change that reaches a renderer: build the gallery with `nsh-widgets build`, package it, place the widget, and save a screenshot under `docs/evidence/<platform>/`. For the KDE renderer: `nsh-widgets plasmoid KIND --group NAME`, install it, and screenshot it under `docs/evidence/kde/`

## Releasing

Bump the version in `Cargo.toml` (root and `[workspace.package]`), `nsh.json` and `packages/nsh-widgets/package.json` together, add the CHANGELOG entry, then tag `vX.Y.Z`. NSH resolves `"version"` requirements against these tags, and the Release workflow attaches the `nsh-widgets` binaries.
